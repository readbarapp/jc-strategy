點樣收錄數據（用日常說話講）

  1. 系統全日每隔大約半個鐘問馬會：「今日沙田或者跑馬地有冇賽馬？第一場幾點開跑？」冇就收工。有就跟當日官方第一場開跑時間倒數，唔係寫死 11:00／17:30。
  2. 開跑前 15、10、5、1 分鐘同開跑嗰下，分別向馬會問兩個獨立彩池：獨贏（WIN）同位置（PLA）。兩個數字分開寫入兩欄，唔會撈亂。唔再抄開賽前 3 分鐘。
  3. 獨贏啡格：呢個鐘點嘅獨贏比起上一個鐘點（大約 5 分鐘前）平咗一半或以上。例如開賽前 1 分鐘同開賽前 5 分鐘比。位置表用同樣方法睇位置急跌，但策略／通知預設仍然用獨贏啡格做訊號。
  4. 賽事完咗再抄官方名次、獨贏派彩、位置派彩（每 $10）。回測「只買位置」用嘅係呢個官方位置派彩，唔係開賽前位置賠率去估。
  5. 而家表入面舊日子係示範假數據。第一次抄到真實馬會賠率／賽果嗰下，程式會刪晒全部示範列，之後回測只睇真實紀錄。
技術細節：點樣向馬會拎賠率（唔係亂填）

第一步問今日有冇賽：向 https://info.cld.hkjc.com/graphql/base/ 送馬會網頁用緊嗰條 GraphQL（raceMeetings）。只接受沙田 ST／跑馬地 HV。

第二步攞中文馬名：同一條 GraphQL 入面 runners 嘅 name_ch。

第三步攞賠率：再問同一端點，參數 oddsTypes: [WIN, PLA]。馬會回兩個 pool：oddsType=WIN 嘅 nodes 寫入 win_odds；oddsType=PLA 寫入 place_odds。每隻馬用馬號（combString）對應，唔會把位置當獨贏。

如果 GraphQL 暫時唔得，後備係馬會舊 JSON：https://bet.hkjc.com/racing/getJSON.aspx?type=winplaodds&date=年-月-日&venue=ST或HV&start=場次&end=場次。回覆字串用 # 切開：前半 WIN;馬號=賠率=…，後半 PLA;馬號=賠率=…。同樣分兩欄存放。

示範數據由 scripts/generate_sample_data.py 產生，只用來填滿表格；真賽日唔會用呢個產生器，而會跑上面兩條馬會通道。

策略參數

揀馬用獨贏啡格＋嗰一刻獨贏賠率範圍（預設開賽前 1 分鐘）。開賽前 1 分鐘嘅啡格係同開賽前 5 分鐘比，唔再同 3 分鐘比。之後先決定點買：$10 獨贏、 $10 位置、定兩者都買。獨贏盈虧用官方獨贏派彩；位置盈虧用官方位置派彩（每 $10）。策略頻率＝總觸發次數 ÷ 賠率樣本入面有幾多個賽馬日（冇觸發嘅賽日都計），大約一個賽馬日有幾多次投注機會。

EV 點計（即使畫面主要見到獨贏）
  1. 訊號永遠睇獨贏：選定時間點（例如 T-1）獨贏較上一個時間點（T-1 就係 T-5，大約 5 分鐘前）跌 ≥ 門檻，而且嗰刻獨贏喺範圍內。
  2. 只買獨贏：中就加官方 win_dividend − $10，唔中 −$10。
  3. 只買位置：同一批馬，但盈虧用 race_results.csv 嘅 placedividend。有派彩先當中；冇派彩就 −$10。唔會用獨贏賠率去估位置派彩。
  4. 獨贏 + 位置：上面兩筆 $10 一齊計，總本金 $20。
  5. EV / ROI = 全部呢啲注嘅淨盈虧 ÷ 總本金。

常見問題


點解表入面有舊日子但寫住示範數據？  


歷史示範係假數據，欄位同真 crawl 一樣。真賽日 Actions 會把真實賠率 追加 入同一個 CSV，唔會用產生器覆蓋真數。


點解開賽前 1 分鐘未見啡格？  


要等 T-5 同 T-1 兩筆都抄到，而且獨贏跌幅真係 ≥ 門檻。3 分鐘位唔會有資料。


收到 Telegram 但網站未更新？  


通知即時送；CSV 最多等兩分鐘先 push。撳「重新載入數據」。


有賽但 job 話今日無賽？  


只認沙田 ST、跑馬地 HV。海外或場外投注日唔會監控。可以喺 Actions 手動跑 monitor 並填日期 YYYY-MM-DD。


回測「只買位置」係咪用開賽前位置賠率？  


唔係。揀馬用獨贏啡格；結算用官方位置派彩。

二、去邊個網站、抄邊啲欄


全部只讀馬會 公開 接口，User-Agent 扮普通 Chrome，Origin / Referer 寫 https://bet.hkjc.com/racing（同官方投注頁一致）。GraphQL query 係馬會網頁用緊嗰條 whitelist；改字段會回 WHITELIST_ERROR，所以程式係原句送出，唔係自己發明 query。


1. 今日有冇賽、場次、中文馬名




網址POST https://info.cld.hkjc.com/graphql/base/


Query 名raceMeetings（QUERY_RACE_MEETINGS_FULL）


參數date = 香港日期 YYYY-MM-DD，venueCode = ST 或 HV


先試沙田，冇 races 再試跑馬地




從 JSON 拎呢啲格：


JSON 路徑用途


raceMeetings[].venueCode場地，只接受 ST / HV


raceMeetings[].date賽日


races[].no第幾場


races[].postTime開跑時間 → 轉成香港 HH:MM:SS


races[].status賽事狀態


runners[].no馬號


runners[].name_ch中文馬名（優先）


runners[].name_en冇中文先用




如果 GraphQL 失敗，後備網頁：




網址https://racing.hkjc.com/racing/information/Chinese/Racing/Fixture.aspx


抄法所有 <a href> 入面 RaceDate=YYYY/MM/DD、`Racecourse=STHV`，或者連結文字有「沙田／Sha Tin」「跑馬地／Happy Valley」


另一後備中文賽果頁 LocalResults.aspx?RaceDate=…&Racecourse=ST&RaceNo=1，用下拉 option 1–14 估有幾場




海外場地會被丟掉。


2. 即時獨贏同位置賠率（主通道）




網址同一個 POST https://info.cld.hkjc.com/graphql/base/


Query 名racing（QUERY_PM_POOLS_ODDS）


參數date、venueCode、raceNo、oddsTypes: ["WIN", "PLA"]




回覆 raceMeetings[0].pmPools[] 係 兩個獨立彩池，唔係一格撈埋：


條件抄邊格寫入邊欄


pmPools[].oddsType == "WIN"每個 oddsNodes[].combString（必須係 1–2 位數字 = 馬號）同 oddsNodes[].oddsValuewin_odds


pmPools[].oddsType == "PLA"同樣 combString + oddsValueplace_odds


其他 oddsType（QIN、QPL…）整池跳過唔寫




combString 對唔到馬號格式（例如連贏組合 1-2）會忽略，避免把複式彩當獨贏。


兩個 map 都空 → 當 GraphQL 失敗，改走後備，唔會把空白當真實賠率。馬名用第 1 步已經備好嘅 name_ch。


3. 即時賠率後備：舊 JSON


官方投注頁沿用嘅接口：


GET https://bet.hkjc.com/racing/getJSON.aspx
    ?type=winplaodds
    &date=YYYY-MM-DD
    &venue=ST 或 HV
    &start=場次
    &end=場次


回覆 JSON 入面 OUT 係一條字串，典型：


WIN;1=8.4=0;2=3.5=0;3=12=1#PLA;1=2.1=0;2=1.4=0;3=3.2=0


點拆：


    

  1. 用 # 切開：前半獨贏，後半位置。
    2. 

  2. 每半邊用 ; 切開。第一段係 WIN 或 PLA 標籤，其餘每段 馬號=賠率=標記。
    3. 

  3. 第一個數字 = 馬號；第二個 = 賠率（寫入對應欄）；第三個官方用來標熱門，程式唔用嚟計啡格。
    4. 

  4. 獨贏 map 同位置 map 分開填，最後用馬號合併成同一隻馬兩欄。
    5. 



所以「crawl 邊一格」喺呢條通道就係：OUT 字串、# 前 WIN 段、# 後 PLA 段、每個 馬號=賠率。


4. 官方賽果同派彩


主通道係中文賽果頁（用瀏覽器打開就係你平日睇派彩嗰版）：


GET https://racing.hkjc.com/racing/information/Chinese/Racing/LocalResults.aspx
    ?RaceDate=YYYY/MM/DD
    &Racecourse=ST 或 HV
    &RaceNo=1 至 14


程式用 BeautifulSoup 搵 整張表文字同時包含「名次」「馬號」「馬名」 嗰個 <table>（英文頁就搵 Pla / Horse No / Horse / Win Odds）。然後按 表頭欄名 對列，唔係死記第幾格，因為馬會間中會加欄：


表頭（中文或英文）寫入


名次 / Pla.finish_rank


馬號 / Horse Nohorse_no


馬名 / Horsehorse_name（去掉尾  (C123) 編號）


獨贏賠率 / Win Oddsfinal_sp（終賠，唔係派彩）




派彩係 另一張表：表內文字有「派彩」或 DIVIDEND。逐行睇第一格：


第一格抄法


獨贏 或 WIN該行馬號 + 金額（例如 52.50）→ win_dividend（每 $10）


位置 或 PLACE該行馬號 + 金額 → placedividend




未中嘅馬派彩寫 0。呢兩個數字先係回測盈虧來源。


GraphQL 後備：resultMeetings，resPools 入面 oddsType WIN／PLA 嘅 dividends[].winComb（馬號）同 div（派彩）。呢條後備好多時 冇名次，所以優先用 HTML 成績表。




三、幾時抄、抄幾密


設定喺 config.json → data（網站數據中心可改門檻同間隔）：


設定預設意思


checkpoints_minutes[15, 10, 5, 1, 0]只認呢幾個鐘點；冇 3


scrape_interval_seconds10高頻時每隔幾秒問馬會


idle_poll_seconds6020 分鐘內都冇場要開，就問得慢啲


monitor_lead_minutes20第一場前幾多分鐘開始密問


monitor_trail_minutes25最後一場後再留幾耐


commit_every_seconds120幾耐先 git push 一次


brown_grid_drop_pct50啡格跌幅門檻




每一場開跑時間 postTime 減而家香港時間 = 仲有幾多分鐘。對落窗口（大約該鐘點 ±1.5 分鐘內先算數）：


標籤大約窗口啡格同邊個比


T-1515.75–13.5 分鐘（第一筆，無比）


T-1010.75–8.5T-15（約 5 分鐘前）


T-55.75–3.5T-10


（3 分鐘）唔抄—


T-11.75–0.5T-5（約 4–5 分鐘前）


T-00.75 至開跑後約 1.5 分鐘T-1




每隻馬每個標籤只寫 一次。10 秒一跳嘅中間數唔存，所以啡格唔會被秒速跳動洗淡。


寫入長表 data/odds_snapshots.csv 一列嘅欄：


race_date, venue, race_no, scheduled_time, checkpoint, capture_timestamp, horse_no, horse_name, win_odds, place_odds, prev_win_odds, win_drop_pct, is_brown_grid


之後 pivot 成寬表 win_board.csv / place_board.csv（一馬一行，T-15…T-0 各一欄）。網站下載鈕匯出嘅就係呢種寬表。odds_board.csv 係獨贏寬表別名。




四、點樣「分析」


啡格（收集當下就算）


跌幅% = (上一時間點獨贏 − 呢個時間點獨贏) / 上一時間點獨贏 × 100
啡格 = 跌幅 ≥ 門檻（預設 50）


例子：T-5 獨贏 8.4，T-1 獨贏 3.8 → (8.4−3.8)/8.4 = 54.8% → 啡格。  


T-1 唔會同 T-3 比（T-3 根本冇資料）。


位置表用 位置賠率 做同樣對比，只供你睇；策略同 Telegram 預設仍然用 獨贏啡格 做訊號。


策略回測（網站即時計，唔使再爬）


讀已經存檔嘅 CSV：


    

  1. 只取你揀嘅 checkpoint（預設 T-1）而且 is_brown_grid 或跌幅 ≥ 門檻。
    2. 

  2. 嗰刻 win_odds 要喺最低–最高範圍。
    3. 

  3. 用 race_date + venue + race_no + horse_no 對賽果。
    4. 

  4. 盈虧：
    5. 



   - 獨贏：win_dividend − 10，派彩 0 就 −10


   - 位置：placedividend − 10（官方位置派彩；唔用開賽前 place_odds 去估）


   - 兩者：兩筆加總，本金 20


    

  1. EV／ROI = 總盈虧 ÷ 總本金。
    2. 



蒙地卡羅：每年落注場次 = 策略頻率 × 一年賽馬日（預設 88）。模擬下注次數係隨機重抽幾多條一年路徑，每條用歷史每注實際 PnL 有放回抽樣，畫資金 P10–P90。




五、點樣 send alert


程式 唔經網站轉發。Actions 跑緊 snapshot_race 寫完一列，即刻喺同一進程呼叫 Telegram。


要全部成立先會送


    

  1. telegram.enabled 開咗，而且有 bot token（Secret 或環境變數）同 chat id。
    2. 

  2. 呢一列嘅 checkpoint 等於 Telegram 設定嗰個（預設 T-1）。其他時間點即使啡格都唔送。
    3. 

  3. 有有效獨贏。
    4. 

  4. win_drop_pct ≥ Telegram 啡格門檻（預設跟數據中心 50%）。
    5. 

  5. 獨贏喺 Telegram 最低–最高範圍。
    6. 

  6. 呢場呢隻馬今日未送過（每馬每場一條）。
    7. 



投注方法（只買獨贏／位置／兩者）唔影響準唔準則，只寫入訊息，提醒你打算點買。


送到邊


POST https://api.telegram.org/bot<TOKEN>/sendMessage


內容包括：日期、場地、場次、開跑時間、馬號、中文馬名、獨贏由邊位跌到邊位、跌幅、當時位置賠率、你揀嘅投注方法、checkpoint、抄低時間（HKT）。


網站「發送測試訊息」會先由瀏覽器打同一條 Bot API；被 CORS 擋就改觸發 Actions test-telegram。
